# [PR 23](https://github.com/vig-os/stepv/pull/23) feat(kernel): sandbox the kernel CLI (Landlock + seccomp, Seatbelt)

## Description

The kernel CLI now sandboxes itself before it opens the input. OCCT's STEP/IGES/BREP readers are a large C++ parser fed untrusted files. If a crafted file triggers a memory-corruption bug, the code it runs can now only:

- read the input's directory and everything below it (multi-file assemblies resolve their external references there);
- write the one mesh file, which the kernel creates before entering the sandbox, so it needs no right to create files.

There is no network, no exec, no process creation, and no other reads or writes.

| Platform | Mechanism | Result |
| --- | --- | --- |
| Linux ≥ 5.13 | Landlock (every right its ABI knows, TCP from ABI 4, scopes from ABI 6) + a seccomp deny list (sockets, exec, any clone without `CLONE_THREAD`, ptrace, namespaces, io_uring, …) returning EPERM | `"sandbox":"landlock+seccomp"` |
| macOS | a deny-by-default Seatbelt profile (`sandbox_init`) | `"sandbox":"macos-profile"` |
| older kernels, or the OS refuses | degrades to what is available, with a warning on stderr; the CLI also warns | `"landlock"`, `"seccomp"`, `"none"` |

The sandbox is in the kernel, not the CLI, so every caller gets it: the GNOME/XFCE thumbnailers, KDE, `stepv view` and the harness. `libstepvocct`, which runs in-process in Quick Look, is left alone, because the App Sandbox is already the boundary there.

## Changes Made

- **Tests first** (`b5c5671`, red): `tests/sandbox.rs` plus the env-gated kernel hook `STEPV_OCCT_TEST_ESCAPE`, which attempts one action from inside the sandbox and reports the outcome on stderr. Seven refusal tests cover TCP, UDP, exec, a write outside the mesh (elsewhere, beside the mesh, into the input dir), an overwrite, and a read outside the input dir. Each asserts the kernel's report, where possible the absence of the effect, and that the mesh is still produced. One test checks that the input's directory and its subdirectories stay readable. Against the unsandboxed kernel, all seven refusal tests **failed**.
- `kernel/sandbox.{h,cpp}`: the sandbox. `kernel/stepv-occt.cpp` resolves both paths, creates the mesh, enters the sandbox, then runs the core, and splices `"sandbox"` into the summary.
- `src/occt.rs` gains `Summary::sandbox` and `Summary::sandboxed()`. The CLI's `kernel` report carries the field and warns on stderr when the sandbox is partial.
- `scripts/test-linux-sandbox.sh`: runs `tests/sandbox.rs` on a real Linux kernel from any podman/docker host (a Debian trixie container with OCCT 7.8.1).
- `scripts/test-macos.sh` holds both extensions to exactly `app-sandbox` + `files.user-selected.read-only`, and checks that the bundled CLI's kernel runs sandboxed.
- **#22** (found on the way): `harness --strict` passed a collapse in which every file failed cleanly. `--min-pass <percent>` now sets a floor, and the Kernel CI gate uses `--min-pass 95`.
- Docs: the README's "contained" claim, plan.md §4 (the decision), §5 (the result), §6 (the read scope), and CHANGELOG.

## [Comment #1](https://github.com/vig-os/stepv/pull/23#issuecomment-5983926740) by [@gerchowl](https://github.com/gerchowl)

_Posted on October 4, 2026 at 08:10 PM_

An independent review of this PR found three real bugs. They are fixed in 18a8aad, test-first again: the new tests fail on the previous kernel on Linux.

1. **A Landlock grant that failed** (for example, a mesh directory that doesn't exist) skipped `landlock_restrict_self`, so the file system was **unrestricted**, and the only trace was `"sandbox":"seccomp"`. Now the ruleset is always entered: it denies by default, so fewer grants only make it stricter.
2. **A symlinked mesh path** made the link's target the writable file. The mesh is now opened `O_NOFOLLOW` and granted by the path its descriptor actually has.
3. **Signals:** `kill(-1, SIGKILL)` was allowed on Landlock ABIs below 6 (for example, Ubuntu 24.04's 6.8). seccomp now lets signals reach this process only, and denies `tkill` and `pidfd_*`. Also added TSYNC.

Also changed:

- an input directly in `$HOME`, in an ancestor of it, or in `/` gets read access to itself only;
- refusals must be EPERM or EACCES, so a test can't pass vacuously on ENOENT;
- each refusal test checks that the full sandbox was in effect.

**The macOS CI failure:** Seatbelt does not nest, so inside nix's build sandbox (`nix flake check`) `sandbox_init` returns EPERM. The kernel now reports that as `"macos-outer"`. Tests step aside only there, when `NIX_BUILD_TOP` is set, and say so. A new workflow step runs `tests/sandbox.rs` and `tests/cli.rs` outside the build sandbox on both lanes. Outside nix, a nested run still fails: I checked with `sandbox-exec` locally.

The ubuntu lane was already green, so Landlock and seccomp work on GitHub's runner kernel.

Also fixed: the harness mislabelled sources for absolute paths, which hid `malformed` from `--strict` and `--min-pass` (#22).
