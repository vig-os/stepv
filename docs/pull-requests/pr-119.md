# [PR 119](https://github.com/vig-os/stepv/pull/119) fix(tests): write test scripts from a child sh, never in the test process

## Description

Fixes #117. On Linux, the integration tests intermittently failed to run their own fake kernels with `Text file busy (os error 26)`, i.e. ETXTBSY.

**Root cause:** the tests wrote each fake-kernel script with `std::fs::write` inside the test process, while other test threads fork (`Command::spawn`). A child forked while that write descriptor is open holds it until the child execs: O_CLOEXEC closes it only at exec, not at fork. Linux refuses to exec a file that any process holds open for writing, so when stepv, or the test itself, exec'd the script, it failed with ETXTBSY. This is rust-lang/rust#114554. macOS has no ETXTBSY, which is why `just view-test` on the Mac never saw it.

**Fix:** `tests/common::executable(path, body)` has a child `sh` write the script and `chmod 755` it. The write descriptor exists only in that `sh`, which has exited before the helper returns. The test process never has it, so no sibling can inherit it. All four writers now use it:
- `cache.rs`: `script()` and the slow kernel;
- `stream.rs`: `Scratch::script()`;
- `progress.rs`: the mute kernel.

**Why not the other options:**
- *Temp name with O_CLOEXEC, then rename:* this doesn't close the race. The forked child holds the descriptor from fork to exec, and the rename keeps the inode, which is what exec checks.
- *Running scripts through `sh <file>`:* this changes what's under test. `STEPV_OCCT` names an executable that stepv execs.
- *Writing scripts before the threads start:* libtest gives no hook for that.
- *A process-wide lock around every spawn:* this would have to cover spawns inside library code too, such as `occt::outline`.

There are no retries and no sleeps.

## Demonstration

Each run was `cargo test --release --test cache --test stream --test progress -- --include-ignored` on an Xvfb with `-noreset`, so the window tests were included. The two tests that need a non-root user were skipped, because the container is root.
