## Changes Made

- **`src/view/`** replaces `src/viewer.rs`:
  - `gpu.rs`: the renderer, independent of egui.
    - Geometry in struct-of-arrays buffers: positions, normals, a face id per vertex, and indices. Each part is a range, drawn as its own instance.
    - Per face, a material (colour and `FaceStatus`) in a storage buffer; per part, its first face in that table and a visibility bitset. No per-vertex colour.
    - It draws into a target the viewer owns: 4× MSAA, resolved to the `Rgba8Unorm` texture egui samples. It doesn't use eframe's attachments.
    - The camera is `render.rs`'s, as an orthographic matrix with the same sphere fit, so both renderers frame a model identically.
  - `app.rs`: the eframe window.
    - A toolbar with view presets, the construction toggle, backend and sandbox pills, and a theme switch; a properties panel; a status bar.
    - The viewport re-renders only when its `RenderKey` changes, so an idle window draws nothing.
    - The scene's CPU copy is dropped once it's on the GPU.
  - `theme.rs`, `widgets.rs`: shadcn-style tokens (zinc neutrals, one blue accent, radius 6, a 4-pt grid) applied through egui's `Style`/`Visuals`, light and dark, with Phosphor icons. Four in-house components: icon button, section header, property row, status pill.
  - `software.rs`: the old minifb window. It's used with `--software`, and automatically, with a note on stderr, when there's no usable adapter.
- **CLI:**
  - `stepv view` reports `"backend": "metal" | "vulkan" | "gl" | "dx12" | "software"`.
  - New options: `--software` and `--theme auto|light|dark`.
  - `STEPV_VIEW_SCREENSHOT=<png>` renders, saves the window and quits. It's the test and screenshot hook.
- **Capi tripwire** (`just capi-tripwire`, CI on both OSes):
  - Fails if stepv-capi's dependency graph contains any of eframe, egui, epaint, winit, wgpu, naga, minifb, ash or glow.
  - Also fails if `libstepv_capi.a` contains a symbol from any of eframe, egui, epaint, winit, wgpu, naga or minifb.
  - Checked red: a unified `-p stepv -p stepv-capi` build turns `viewer` on, and the tripwire names nine crates.
- **CI** (`kernel.yml`, macOS): `just view-test` with `STEPV_REQUIRE_GPU=1` runs the renderer's tests on Metal, then real windows: both themes, `--software`, and the fallback.
  - Linux gets the same in CI in #32. Until then, `just linux-view-test` runs it locally in a container on lavapipe + Xvfb.
- **Licences:** egui embeds fonts under OFL-1.1 and the Ubuntu Font Licence, and arboard's Windows clipboard is BSL-1.0.
  - All three are allowed in `deny.toml`, with the reason recorded.
  - The font licence texts are in `licenses/`, which every package ships, and NOTICE lists them.

## Changelog Entry

### Added
- **GPU viewer** ([#28](https://github.com/vig-os/stepv/issues/28), for [#21](https://github.com/vig-os/stepv/issues/21)): `stepv view` draws on the GPU through egui + wgpu (Metal, Vulkan or GL)
  - Per-face colours come from a storage buffer, and parts can be hidden, without touching the geometry. The framing is the thumbnails' own
  - A toolbar, a properties panel and a status bar
  - Light and dark themes from shadcn-style design tokens, following the OS or `--theme`
  - The pre-#28 software window is kept as `--software`, and taken automatically, with a note, when there is no usable GPU adapter. The JSON line reports `"backend"`
  - CI checks that the Quick Look library never links the window or GPU stack

### Manual Testing Details

**Stress assembly** (1.77M triangles, 240 parts), Apple M3 Ultra, Metal:
- upload: 43 ms;
- GPU-synchronised frame at 1280×800, 4× MSAA: p50 0.88 ms, p95 1.37 ms (the ignored `stress_assembly_draws_at_display_rate` test);
- the viewer's steady footprint is about 360 MB, of which 98 MB is GPU memory. The rest is system frameworks: malloc_history shows no stepv allocation of 1 MB or more after the upload;
- the 2.1 GB the #27 prototype was charged with is the kernel child's peak (2078 MB), not the viewer's.

## Additional Notes

- **Review:** a fresh code-reviewer agent reviewed `3ddb161` and blocked it. All nine findings are fixed in `91fce7c`:
  - **The blocker:** the software fallback covered only the probe's adapter. eframe picked its own, so an adapter that couldn't run the pipelines would have panicked with no JSON line. eframe now chooses its adapter through `gpu::select`, and pipeline creation runs inside an error scope. `test-viewer.sh` covers this path.
  - **Nits:**
    - `usable()` and `limits()` disagreed;
    - the base-vertex check was missing;
    - approximated faces had lost their stripes; they're restored, with a test;
    - the viewport texture wasn't clamped to the device's size limit;
    - the screenshot hook could spin forever;
    - `test-viewer.sh` lost the diagnosis when a run failed;
    - the vertex split scanned linearly;
    - the theme toggle rebuilt the font atlas.
- **Out of scope here, queued:** picking (#29), the tree (#30), the FaceStatus overlay and B-rep edges (#31), the Linux CI smoke test and packaging (#32).
