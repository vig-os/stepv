# [PR 46](https://github.com/vig-os/stepv/pull/46) fix(kernel): a failed topology no longer fails the run

Closes #38.

## What
The exact topology (`--topology`) comes after the mesh. When it failed (an OCCT exception in one prototype, an unwritable file), the whole run failed with it, and `--png --topology` lost a good PNG.

- **Kernel** (`kernel/stepv-occt-core.cpp`, `kernel/topology.cpp`): a topology failure is recorded as `topology_error` in the JSON summary, and the run succeeds with its mesh. `write_topology` leaves no partial file: it empties and removes what it wrote. Inside the CLI's sandbox it can only empty the file, and the parent removes it.
- **CLI** (`src/main.rs`): `topology_error` is in the report, both top level and under `kernel`, beside a `--png`/`--glb`/`--mesh` output, with exit 0. An older topology at the destination is removed, so it can't pass for this model's. `--topology` alone still fails (exit 3).
- **`stepv view`**: the `topology_failed` retry is gone. It's one kernel run, then the viewer opens without the inspector and says why.
- **Test hook** `STEPV_OCCT_TEST_TOPOLOGY_FAIL`: makes `prototype_json` throw, like `STEPV_OCCT_TEST_BALLOON_MB` does for memory.

## Budget decision (the issue's pitfall)
**The topology keeps sharing the run's `--timeout` and memory cap. It gets no budget of its own.** The limits protect the machine, and the parent enforces them by killing the kernel, which can't keep half a run. Running out of memory stays fatal, also from a prototype's worker thread, so it is still reported as `memory-cap`. A file that fits its limits only without the topology still fails with it, as plan.md now says.

## Tests (red before, green after)
- `tests/cli.rs`:
  - `a_failed_topology_keeps_the_png`: the PNG is written, exit 0, `topology_error` is set, and the stale destination file is gone.
  - `a_failed_topology_alone_fails`: exit 3.
  - `an_unwritable_topology_keeps_the_mesh`: the kernel itself, given an unopenable `--topology` path.
- `scripts/test-viewer.sh` step 9: `stepv view` with the hook opens, reports the failure, and makes exactly **one** kernel run, counted through a `STEPV_OCCT` wrapper. Before the fix it made two (the retry).

Locally:
- `STEPV_REQUIRE_GPU=1 just test` passes;
- `just macos-test` passes;
- `scripts/test-viewer.sh` passes;
- `just linux-view-test` passed in full, including step 9 on lavapipe.

The first Linux run segfaulted in the `view::` unit tests, which this PR doesn't touch, and the rerun was clean. That flake is filed as #45.
