# [PR 52](https://github.com/vig-os/stepv/pull/52) test(corpus): add seven CAD writers and a real large assembly

## Description

Fills #12's corpus gaps as far as public sources allow. Every file is fetched by `just fixtures`, pinned by sha256, and never committed.

- **`exporter-matrix`**: one file per writer. Each writer was read from the file's own `FILE_NAME` header: SolidWorks 2015, NX 9.0, CATIA V5 R14, Fusion 360, FreeCAD/OCC, Inventor 2021 and Creo.
- **`real-assembly`**: the whole Ultimaker 3 printer, one 143 MB SolidWorks 2016 STEP with 523 parts. **CC BY-NC 3.0**: fine to fetch and test against, never to redistribute. This is flagged in the manifest.
- **`mbx-if-public`**: MBx-IF's one open AP242 model. The full CAx-IF rounds are members-only, shared by invitation, so `cax-if` stays MISSING. This is the one part of #12's acceptance that public sources can't meet.

**Finding:** the real assembly loads correctly but takes **100.7 s, of which 92.2 s is STEP transfer**. That's past the CLI's 20 s default, so the file can't be previewed today. Filed as #51.

## Changes Made

- `scripts/fetch-fixtures.py`:
  - a `files` fetch kind: single files, each pinned by sha256; a file already present isn't refetched, and a `name` can't escape the source directory;
  - `corpus_name()`, which skips `__MACOSX/` and `._*` AppleDouble entries in zips, git trees and the lock. The Ultimaker zip carries `__MACOSX/._9066.STEP`.
- `scripts/test_fetch_fixtures.py`: 8 offline stdlib tests (file:// URLs). They cover the zip filter, the `files` kind (placement, a hash mismatch, no refetch, path escape) and the committed manifest (known kinds, `why`/`license`/`expect` on every source, commit-pinned URLs with a writer on every file). `just test` runs them.
- `tests/fixtures/manifest.toml`: the three sources above, and `cax-if`'s note says why it stays hand-collected.
- `tests/fixtures/corpus.sha256`: regenerated, 410 files.
- `plan.md`: §5 "Corpus fill (#12)" with the harness table, the status line, the S1 caveats pointer and the work queue.
- `.gitignore` and `.gitignore.project`: `__pycache__/`.

**After the fresh review (approve, no blockers), in `4320a99`:**
- `kernel/stress-gen.cpp` writes a fixed `FILE_NAME` time stamp. OCCT stamped the wall clock, so `stress-assembly` hashed differently on every regeneration, and `corpus.sha256` wasn't exact. `tests/cli.rs` `stress_gen_output_is_byte_reproducible` generates twice, a second apart; it failed before the fix and passes after.
- `examples/harness.rs` `collect()` skips `__MACOSX/` and `._*`, like the fetcher, with a new unit test that failed first. The harness's unit tests never ran before, because `cargo test` skips example tests, so `just test` now runs `cargo test --release --example harness`.
- `fetch_zip` uses the same `inside()` escape guard as `fetch_files`. The fetch kinds are one `FETCHERS` table, which the manifest test reads instead of a copied set. There are new tests for absolute, `""`, `.` and `a/../..` names, and for a zip-slip entry.
- The wording: 99.2% is "faithful or wireframe" (99.0% fully faithful).
