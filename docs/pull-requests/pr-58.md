# [PR 58](https://github.com/vig-os/stepv/pull/58) feat(kernel): read the assembly outline before the geometry

## Description

The first step of #54: the assembly tree and names **before** the geometry. `stepv-occt --outline` walks the parsed `StepData_StepModel` with **no shape transfer** and prints one JSON line in `--topology`'s tree format. On the 143 MB Ultimaker 3 assembly it answers in **4.6 s; the full run takes 98.6 s** (#51).

**The contract** (`kernel/outline.h`) is the *product* level of the tree `--topology` writes, `topology::products`:
- a product the transfer splits into unnamed bodies is one leaf (AP203 hybrid models: a solid plus a wireframe, sometimes nested a level);
- shapeless products, such as materials, are left out, as the transfer leaves them out;
- the geometry's tree replaces the outline when it arrives.

**A deliberate gap:** a multi-file assembly's products that live in other files are leaves. The outline reads only the file it is given.

**Corpus check** (all 390 local STEP files except `malformed`, plus Ultimaker 3): the outline was compared with `products()` of the full run's tree. **388 agree exactly**; the two others are the multi-file gap (`s1-c5-214`, `s1_pe_214`). That took two rounds:
- An exact-tree contract agreed on 347. It failed on hybrid-model bodies and shapeless material products, which led to the product-level contract.
- The collapse rule then had to cover nested unnamed groups (NIST CTC 02 AP242).

**After the fresh review (approve, no blockers), in `a3ef540`:**
- `--serve --outline`, and `--outline` with `--mesh`/`--topology`, are refused right after parsing, before any output is created (and so truncated). `tests/outline.rs` checks that no file appears.
- `has_shape` follows `getSDR`: an SDR with a representation, or one reached through a non-GD&T `SHAPE_ASPECT`. `shown()` recurses and is memoised, so an assembly of shapeless products is dropped too.
- Bounded at 60 levels, inside serde_json's nesting limit of 128, and at a million nodes, because shared sub-assemblies expand per instance and the C API runs in-process.
- The known gaps (multi-file; a product with sub-assemblies and its own shape; an all-unnamed real sub-assembly) are listed in `outline.h`.
- **A CI gate:** `harness --outline` compares each STEP file's outline with `products()` of its run's tree, and the Kernel lane's `--strict` now fails on a mismatch. Locally on NIST and `tests/data`: 37 agree, 0 differ, 1 multi-file not compared. The full local corpus is still 388/390.

## Changes Made

- `kernel/outline.{h,cpp}`: the walker. It mirrors the transfer's roots (`RootForTransfer`) and NAUO order (`STEPControl_ActorRead::TransferEntity`), and `STEPCAFControl_Reader::ReadNames`' naming, with the kernel's `walk` rules on top.
- `kernel/stepv-occt.cpp`: `--outline`, sandboxed with nothing writable, like `--serve`. It can't be combined with outputs.
- `kernel/stepv_occt.h` and `stepv-occt-core.cpp`: `stepv_occt_outline` in the C API, for the macOS step. The serialising mutex is hoisted so outline and run calls share it.
- `src/occt.rs`:
  - `run()`'s timeout and memory-cap loop is extracted into `supervise()`;
  - `occt::outline()` uses it and validates format, version and leaf numbering.
- `src/topology.rs`: `products()`, and `PartialEq` on `Node`.
- `tests/outline.rs`: outline vs `products(--topology)` on the five `tests/data` STEP files; the leaf count; IGES/BREP refused; noise fails cleanly.
- `.typos.toml`: OCCT's `UsefullLength` (sic).
- `plan.md` "Outline before geometry (#54, step 1)", `CHANGELOG.md`.

### Added
- **The assembly outline before the geometry** ([#54](https://github.com/vig-os/stepv/issues/54)): `stepv-occt --outline` reads a STEP file's product tree and names straight from its parsed entities, with no shape transfer. On the 143 MB Ultimaker 3 assembly that takes 4.9 s against 102 s for the full run ([#51](https://github.com/vig-os/stepv/issues/51)), so a front-end can show the tree while the geometry loads
  - It is the product level of the tree `--topology` writes: the same products, names and order. A product the transfer splits into unnamed bodies is one leaf (`topology::products`)
  - In the C API as `stepv_occt_outline`, and in Rust as `occt::outline`
