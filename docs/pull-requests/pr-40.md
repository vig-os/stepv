## Changes Made

- **STEPVMSH v4** (`kernel/stepv-occt-core.cpp`, the format at the top):
  - `stepv-occt --edges` appends each part's B-rep edges as polylines: `edges`, `edge_ids`, `edge_lens`, then the points. They're sampled at the mesh's deflection.
  - They are numbered by `stepv::topology_edges`, which `--topology` now uses too, so an edge id names its JSON curve by construction.
  - The C ABI gains `stepv_occt_run_ex`; the existing entry points are unchanged.
- **Who gets v4:** only `stepv view` asks for it. Thumbnails, `--glb`, `--mesh` and Quick Look stay on v3, as the issue allowed.
  - The Rust reader reads v3 and v4, bounding every count before allocating.
  - The Swift reader accepts v4 and skips the edges.
- **Drawing** (`src/view/gpu.rs`): a near-black LineList, pulled 0.0005 depth units toward the eye in the vertex shader. WebGPU allows no depth bias on lines, so this is how an edge beats the faces it bounds. E or the toolbar toggles the edges.
- **Edge picking:** the id pass draws edges as `EDGE_BIT | edge`.
  - A click reads a 9×9 window, and the nearest edge within 4 px wins (`resolve_pick`), since a one-pixel line is otherwise unclickable.
  - `inspect::edge` shows the curve: a circle's radius, ⌀, centre and normal, or an ellipse's two radii. It also shows the length, scaled with the instance.
  - A picked edge draws in the accent colour.
- **One overlay rule:** `render::overlay(status)` decides which faces are striped. `render.rs` uses it, and the GPU materials carry its value instead of the raw status.
