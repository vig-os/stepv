## Description

The last part of #62 (#54 step 4): the outline artifact. A cached CLI run now leaves the file's header and assembly tree in the cache as soon as the kernel streams the outline. A run that is then killed or times out still leaves something a preview can show at once. #68 (atomic, versioned entries) and #69 (only complete results and failures of the input) are already merged.

## Changes Made

- **`cache::OutlineArtifact`:** JSON `{format: "stepv-outline-artifact", version: 1, header, tree, leaves, bbox, boxes}`, stored at `<key>.outline.json`.
  - **Key:** (path, len, mtime) alone, in its own hash domain, so the artifact doesn't depend on the render options.
  - **One snapshot per run (`cache::FileId`):** taken before anything reads the file. Both the entry's key and the artifact's are made from it, so a file saved mid-run gets nothing from that run.
  - **Writes:** atomic, through #68's `write_atomic`, as versioned JSON without #68's magic and checksum (plan.md says why). The outline is written only when no current-version artifact is at its key, so a later run killed after its outline keeps an earlier run's box.
  - **API:** a write takes a path from `cache::outline_path(dir, &FileId)`, so nothing stats the file at write time. `store_outline_in`, which did, is removed.
  - **Reads:** `cache::load_outline` / `load_outline_in` read it back for #63's thumbnail fallback, and reject another format or version.
- **`src/main.rs`:** cached runs (`--png`/`--glb`/`--mesh`/`--topology`, without `--no-cache`) are streamed through `occt::run_streaming`.
  - The artifact is written on `Event::Tree`, before the transfer.
  - The run adds the model's `bbox` only once the mesh has decoded.
  - `boxes` stays absent until the kernel streams per-part boxes (#66).
- **A kernel that exits 0 or 3 without its summary:** status `error`, "bad kernel output: the kernel exited without a summary", on the plain and the streamed path alike, and not cached. `occt::run_streaming` now gives a broken stream the exit's outcome, as `occt::run` does, instead of `Crashed`. Any other exit is still a crash.
- **`header.rs` / `topology.rs`:** the header gains `Deserialize` and the tree gains `Serialize`, so the artifact can be written and read back.

**Fix round 1:** each new test above failed before the fix:
- the mid-run save: the saved file was served the run's artifact;
- the undecodable mesh: the box was stored anyway;
- the killed later run: it dropped the box;
- the missing summary: `crashed` instead of `error`.

The mtime-only case already passed, since the key always included the mtime.

The other two criteria (truncated or old-version entries are regenerated; concurrent writers never tear an entry) were covered and merged in #68.

## Additional Notes

Known limits, each tracked:
- **Per-part boxes:** `boxes` is always absent. #66.
- **`view` doesn't write the artifact yet.** #63 (noted there).
- **Timeout cost:** a streamed run pays for the outline's parse inside its timeout, about 5% on a large assembly, so a run near its cap can time out where a plain run wouldn't. #76.
- **IGES/BREP:** they have no outline, so they leave no artifact. #76.
- **The cache key** (shared with the entries):
  - a file rewritten in place, at the same length, within one mtime tick, is taken for the old one;
  - a multi-file assembly's part files are outside the key.

  Both are #77.
- **Concurrent runs (#80):** a box can still be lost. Run A checks for an artifact (a read and a JSON parse) and finds none. Run B, completing, then renames its artifact with the box into place, and A's outline write (create, write, `sync_all`, rename) replaces it. The box is missing until the next complete run. The window runs from A's read to A's rename, milliseconds or more on a real disk. #80 proposes a lock file or a no-replace rename.
- **A cache hit writes no artifact:** it returns before the kernel runs, so a file cached before this PR gets no outline until its entry misses. #76.
- **Flaky test:** the existing `tests/stream.rs` kill test's 3 s cap flakes under load (#67). The new kill test uses a 10 s cap.

Closes #62
