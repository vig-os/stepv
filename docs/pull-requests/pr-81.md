# [PR 81](https://github.com/vig-os/stepv/pull/81) perf(kernel): build OCCT with the FixSelfIntersectWire hoist patch

Refs: #74

## What

stepv now builds OCCT 7.9.3 with one patch, the corrected hoist from the #74 gate, to `ShapeFix_IntersectionTool::FixSelfIntersectWire`. The patch fetches `edge1` once per `num1`, and fetches it again after the big-segment branch's `Remove(numseg2); Remove(numseg1)`. Healing a wire of n edges drops from O(n³) to O(n²). The results don't change.

- **`flake.nix`**:
  - `occt = pkgs.opencascade-occt.overrideAttrs { patches = [ ./nix/patches/occt-7.9.3-fixselfintersectwire-hoist.patch ]; }`. The dev shell (`just kernel`, the macOS app's dylibs) and the kernel derivation (the product, the Linux tarball, `nix flake check`) all use it.
  - A patch that doesn't apply fails `patchPhase`, and an OCCT version other than 7.9.3 fails evaluation.
- **NOTICE**: describes the modification and its LGPL-2.1 terms. It locates the patch in the release's source archive.
- **The patched file**: carries a dated notice that it was modified.
- **`nix/patches/`**: excluded from the whitespace hooks.

## Tests

`kernel/occt-patch-check` is built beside the kernel with `-DSTEPV_BUILD_TESTS=ON`, against the same OCCT, and `tests/occt_patch.rs` runs it:

- **`fix_self_intersect_wire_is_quadratic`**: the growth exponent of the fix time from an 800-gon to a 3200-gon, which is a ratio of CPU times rather than a wall-clock threshold. The threshold is **2.5**: the test requires < 2.5.
  - Patched: 2.03.
  - Unpatched, from this PR's CI: 2.940 on aarch64-darwin, 2.880 on x86_64-linux.
- **`fix_self_intersect_wire_matches_unpatched_occt`**: 200 generated wires, 91 of which go through the big-segment branch. Each must come out exactly as **this platform's** reference, `tests/occt-patch/wires-{aarch64-darwin,x86_64-linux}.txt`, which was recorded with nixpkgs' unpatched OCCT on that platform.
  - Why one file per platform: OCCT's own floating-point results differ across platforms. Unpatched, x86_64-linux splits seed 194 once more than aarch64-darwin. The cause (compiler or architecture) is unconfirmed. The generator uses integers only.
  - A hoist without the re-fetch fails on 39 seeds. A platform with no reference fails the test; it is never skipped.
- **Provenance check, `checks.<system>.occt-patch-reference`**: builds the check tool against nixpkgs' **unpatched** `pkgs.opencascade-occt` from cache.nixos.org. That build must reproduce the platform's reference byte for byte, and must **fail** the scaling test (exponent ≥ 2.5). In CI it passes on unpatched OCCT, with 2.940 on aarch64-darwin and 2.880 on x86_64-linux, both ≥ 2.5. Pointed at the patched OCCT (2.03) it fails. Both kernel lanes run it in `nix flake check`.

## Binary cache

The patched OCCT is in no public cache. It takes about 35 min to build on sage and about 55 min on a GitHub Linux runner.

- **Cache**: the public Cachix cache `gerchowl`, seeded for aarch64-darwin (from sage) and x86_64-linux (built on anvil, pushed from sage).
- **Pull**: always, through `cachix/cachix-action` (pinned v17) in `kernel.yml` and `release-extension.yml`.
- **Push boundary**: pushes come only from `main` (a push or a dispatch) and from the release run. A pull request gets no token: `authToken` is empty and `skipPush` is true. The step "A pull request holds no Cachix token" fails the run if `cachix.dhall` or `CACHIX_AUTH_TOKEN` is present.
- **Open, devkit-managed**: `ci.yml` still passes the token on same-repo PRs. This is tracked in vig-os/devkit#1881.
- **Docs**: plan.md §7 "Binary cache" covers the key, how to opt in through nix.conf (the flake has no `nixConfig`), and token rotation.

## Evidence

- **Corpus**: 401 files, 0 differ.
- **Ultimaker 3**: the mesh and topology are byte-identical. The transfer takes 28.8 s instead of 35.0–36.4 s, and the same 4 faces are over budget.
- **`num1` range after the removals**: `NbEdges() >= num1 + dnum1 >= num1`, so `num1` is always in range and no guard is needed (plan.md "#74 OCCT patch").
- **CI**: everything passes except Kernel (macos-15), whose `just macos-test` supervisor check fails the same way on main (tracked in #111). On both lanes, `occt_patch` and `occt-patch-reference` pass and OCCT is substituted from `gerchowl.cachix.org`.
