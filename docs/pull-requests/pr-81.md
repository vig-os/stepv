# [PR 81](https://github.com/vig-os/stepv/pull/81) perf(kernel): build OCCT with the FixSelfIntersectWire hoist patch

Refs: #74

## What

stepv now builds OCCT 7.9.3 with one patch, the corrected hoist from the #74 gate, in `ShapeFix_IntersectionTool::FixSelfIntersectWire`. The patch fetches `edge1` once per `num1`, and fetches it again after the big-segment branch's `Remove(numseg2); Remove(numseg1)`. Healing a wire of n edges drops from O(n³) to O(n²), and the results don't change.

- **`flake.nix`**: `occt = pkgs.opencascade-occt.overrideAttrs { patches = [ ./nix/patches/occt-7.9.3-fixselfintersectwire-hoist.patch ]; }`. The dev shell (`just kernel`, the macOS app's dylibs) and the kernel derivation (the product, the Linux tarball, `nix flake check`) all use it.
  - If the patch doesn't apply, `patchPhase` fails.
  - If nixpkgs ships an OCCT other than 7.9.3, evaluation fails.
  - `nix/patches/` is excluded from the whitespace hooks, which would strip the patch's single-space context lines.
- **The patched file** carries a dated notice that it was modified, as LGPL-2.1 §2(a) requires.

## Tests

`kernel/occt-patch-check` is built beside the kernel against the same OCCT, and `tests/occt_patch.rs` runs it:

- **`fix_self_intersect_wire_is_quadratic`** measures how the fix time grows from a convex 800-gon to a 3200-gon, as a ratio of CPU times rather than a wall-clock threshold. The test requires an exponent below 2.5. Patched it is 2.00–2.01; unpatched it is 3.00–3.06, and the test fails with `grows as n^3.05`. A deterministic count isn't possible from outside OCCT: the cost is the walk inside `NCollection_BaseSequence::Find`.
- **`fix_self_intersect_wire_matches_unpatched_occt`** generates 200 wires with splitmix64, so they are the same on every platform. 91 of them go through the big-segment branch. Each must come out exactly as `tests/occt-patch/wires.txt`, which was recorded with nixpkgs' **unpatched** OCCT. The gate's hoist without the re-fetch fails it on 39 seeds.
