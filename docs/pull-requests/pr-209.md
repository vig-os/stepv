# [PR 209](https://github.com/vig-os/stepv/pull/209) feat(mesh): M2, planar faces with holes

Fixes #144

## What
**M2 of ADR-0001 §2.6: planar faces with holes.** `stepv::mesh::plane::mesh(g, face, &polylines, Context { mm_per_unit, uncertainty }, reversed)` turns one `ADVANCED_FACE` on a `PLANE` into a `FaceMesh`. It's a struct of arrays: an `EdgePoint` and x/y/z per vertex, `[u32; 3]` triangles, and one exact normal. If the face can't be meshed, it returns a `Route` with its reason.

- **Boundary.** Each bound's loop is built from the shared edge polylines (`Polylines::oriented`), joined at bit-identical ends and reversed for `orientation = .F.`. The vertices are those points, bit for bit. No Steiner point is added, and no constraint is ever split.
- **Inversion.** Every point is checked on the plane, `|(p − o)·z| ≤ uncertainty + 8ε(|p| + |o|)`, before it gets its (u, v). The second term is f64's own rounding of the distance. ABC `00000046` writes an uncertainty of 1e-17 mm, which f64 can't check: a point exactly on the plane computes as 9e-17 off it.
- **CDT (`spade`).** All points are inserted first, then every segment is added with `try_add_constraint`. A segment is routed when it:
  - crosses another (`rs-fail:cdt-crossing`);
  - passes through a vertex (`rs-fail:cdt-touching`);
  - repeats an existing segment (`rs-fail:loops-overlap`).

  Loops are also checked: `loop:open`, `loop:degenerate`, `loop:self-touching`, and `rs-fail:coincident` (two different 3-D points at the same (u, v)).
- **Flood.** The flood starts from the outside, and crossing any constraint toggles inside/outside. So it needs no outer loop: a face with only `FACE_BOUND`s is handled the same way as one with a `FACE_OUTER_BOUND`.
- **Orientation (ISO 10303-42).** The face must lie to the left of every oriented bound, seen from the topological normal (z, or −z when `same_sense = .F.`). The check covers every segment and is exact, because both sides of it are combinatorial; a failure routes `rs-fail:orientation`. The corpus has 0 such failures.
- **Normals.** The normal is exact: z, flipped by `same_sense` and by the caller's `reversed` (the face's orientation in its shell). An edge routed by `mesh::edges` routes the face: `edge routed: <reason>`.
- **`graph`.** `curve::{advanced_face, face_bound, plane}` are new, and `graph::length_uncertainty` is now public (it was fit.rs's private `uncertainty`).
- **`spade = "=2.15.1"`.** Licence MIT OR Apache-2.0, compatible with Apache-2.0. It adds `robust` 1.2.0 (MIT OR Apache-2.0); the other dependencies were already locked. `cargo deny check` passes: advisories, bans, licences, sources.

## Golden (`tests/mesh_plane.rs`, new CI step on nist-pmi + occt-import-js)
- **Comparison.** Each planar face's mesh area is compared with the kernel's `--topology` face area (`BRepGProp`) within 1e-6 relative. Before comparing, the exact chord-to-curve area of each circle or ellipse segment is added.
  - A B-spline chord's error is bounded by d·|chord|.
  - A vertex that lies g off one of its lines or conics, within the file's uncertainty, moves every edge it ends by at most g·(L + 2g). This is needed because OCCT's face follows the curve, while Rust's follows the vertex.
  - If a vertex lies off its curve by more than the uncertainty, the face is undefined. It is counted but not compared, and Rust should route it (#207).
- **The join is G7's:** transfer order, checked by face count, surface type and the graph's face box. A product's kernel parts are pooled over every leaf it is, one per prototype. If the join fails, each Rust area must match an unused OCCT plane face area, tightest bound first.
- **What fails the gate:** a file that can't be compared, a face area that matches nothing, or a normal that isn't parallel to OCCT's.
- **CI corpus: 88 files, 102 products:**
  - 2,543 faces match exactly (worst 5.3e-8 relative);
  - 243 match within their bound;
  - 350 of all matches were made by value, in 9 unjoined parts;
  - 6 faces are routed (`loop:self-touching` 3, `rs-fail:coincident` 3; #208);
  - 2 faces have a vertex off its curve beyond the uncertainty;
  - **0 failing**, 0 opposite normals, 0 files not compared.
- **`tests/data` + a perforated-plate fixture:** 25 faces match exactly, worst 4.2e-16.
- **ABC, run locally (298 files; `00000048` left out because the kernel exits 86 on it):**
  - 18,173 faces match exactly (worst 3.2e-9), 1,971 within their bound, **0 failing**.
  - Every ABC file declares an uncertainty of 1e-17 mm. Because of that, 5,703 faces route `curve:off-surface` and 4,788 have a vertex off its curve beyond the uncertainty.
  - I filed this as a design question for the owner: #210.

## Stress: ABC `00000046`
Set `STEPV_PLATE` to run it, following the `STEPV_CORPUS` pattern: unset, it skips loudly; set to a missing file, it fails.

Run with `--release`: 6 planar faces, two of them with **2,499 holes each**, mesh into 99,972 triangles in **0.11 s**, plus 0.04 s for the graph and polylines. Peak RSS is **45–49 MB**. OCCT takes 7.7 s and 4.2 GB. ADR §6 and plan.md say "1,250 holes", but the file has 2,499 cylinders; the ADR's M2 notes record this.

## Tests
- `nix develop -c cargo test mesh::plane`: 15 unit tests, exit 0. They cover:
  - a square, including one on a tilted plane;
  - one circular hole, and a hole whose `orientation = .F.`;
  - 144 holes with only `FACE_BOUND`s;
  - a hole touching the outer loop at a vertex (meshed) and at the inside of a segment (routed `cdt-touching`);
  - a concave U shape;
  - `same_sense = .F.` (normal and winding flipped) and `reversed`;
  - wrong orientation;
  - bow tie, two-point loop, zero-length segment (`loop:degenerate`), collinear loop and figure eight, each routed with its reason;
  - an open loop, off-plane points, an edge routed in `mesh::edges`, and a surface that isn't a plane;
  - two coplanar faces sharing an arc: the same points, bit for bit, in opposite order;
  - 1e50 mm meshes with finite output, and 1e100 mm is routed;
  - an uncertainty below f64's rounding.

  Every mesh is checked to: equal the loops' area, have no triangle outside the face or with zero area, use the edge polyline's points exactly, and be finite.
- `nix develop -c cargo test --test mesh_plane`, with the corpus as above: exit 0.
- Local gate (`fmt --check`, `clippy --all-targets -D warnings`, full `cargo test`): exit 0. `cargo doc -D warnings` and `cargo deny check` also pass.
- **Pre-change failure.** I disabled the flood so it keeps every triangle; 7 of the 15 unit tests fail, for example: `a_square_with_a_circular_hole … panicked at src/mesh/plane/tests.rs:200: triangle … in a hole`.
