# [PR 26](https://github.com/vig-os/stepv/pull/26) feat(kernel): export the exact topology (--topology)

## Description

The kernel side of #21, the viewer with a model tree, sections and measurements. Whichever viewer platform is chosen (A native macOS, B cross-platform Rust, or C both), it needs the exact topology that the kernel used to discard. With this PR, `stepv-occt --topology <out.json>` and `stepv --topology <path>` write it:

- the **assembly tree**, with names (the mesh only had the flattened parts);
- per placed **part**: its prototype and its 3x4 placement;
- per **prototype**: area, volume (closed shells only) and bbox;
- per **face**: its surface type and parameters (a plane's true outward normal; the axis and radius of cylinders, cones, spheres and tori), its area, and its edges;
- per **edge**: its curve (a circle's centre and radius), its length, and its vertices; and the vertex positions.

The indices line up with the mesh's: `parts[i]` is mesh part `i`, and a prototype's `faces[j]` is mesh face id `j`, so a picked triangle names its exact face. The format is specified at the top of `kernel/topology.cpp`, with Rust types in `src/topology.rs`.

The viewer itself is **not** in this PR. Its platform needs your decision on #21.

## Changes Made

- **`kernel/topology.{h,cpp}`:** the writer.
  - Prototypes are computed in parallel (`OSD_Parallel`).
  - Lines and circles take their length in closed form. Together these took the 221 MB stress assembly (39,840 faces) from 17.7 s to 0.6 s, with identical results.
  - Every number written is guarded against NaN and infinity.
- **`kernel/stepv-occt-core.cpp`:** `walk()` records the tree, and `run()` writes the topology on request. New C ABI `stepv_occt_run_topology`; `stepv_occt_run` is unchanged.
- **`kernel/stepv-occt.cpp` and `kernel/sandbox.*`:** `--topology`. The sandbox grants a list of writable files: the mesh and the topology, each by its descriptor's path, and nothing else.
- **`src/topology.rs`:**
  - `Topology::parse` checks the format, the version and every index.
  - `Topology::check_against` holds the file to the mesh it came with.
  - The CLI refuses a file that fails either check, as a stepv bug.
- **`src/main.rs`:** `--topology` works beside any output or alone. It bypasses the cache, since it needs the kernel anyway.
- **`kernel/json.h`:** the shared JSON escaper, moved out of the core.
- **Docs:** README, CHANGELOG (Added), and plan.md (§5 "Topology export", and the work queue).

**Found on the way, fixed:**

- The kernel truncated an output whose path was the **input file**, which would have destroyed the file being previewed. This predates this PR; `--mesh` had it too. It now exits 2 without touching anything.
- `--info` silently ignored any output flag; it now refuses them.

### Manual Testing Details

- **Hand-calculated values:**
  - the bracket plate's volume is 6000 − 80π, its area is the closed-form sum, and its hole radius is 4;
  - the pin's volume is 60π, and its placements are (6, 15) and (34, 15);

  - the sketch is one circle of radius 25 with no volume;
  - a plane with left-handed axes reports its true normal: −z, where `Axis()` says +z. This test fails without the fix.
- **Corpus:** over all 401 files, `--topology` changes no exit code, and every file it writes parses. Total wall time goes from 295 s to 362 s; the worst file gains 5 s.
- **Sandbox:** `the_topology_is_the_one_other_writable_file` passes on macOS and on Linux 7.0 (`scripts/test-linux-sandbox.sh`, 13/13). The parallel topology runs under seccomp.
- **Output aliasing:** `an_output_on_the_input_is_refused_untouched`.
- An independent code review: the plane normal, NaN handling and output aliasing above came from it and are fixed. It found no thread-safety problem.

## Additional Notes

**Not in v1:** edge polylines, which a viewer needs in order to pick edges on screen. They belong in the mesh (STEPVMSH v4) once the viewer exists. Shape-to-shape distances (`BRepExtrema_DistShapeShape`) are on-demand queries, not precomputed data.

**A choice for review:** when `--topology` is requested and a prototype's topology throws, the whole run fails, even if the mesh was fine. The corpus never hits this.
