# [PR 69](https://github.com/vig-os/stepv/pull/69) fix(cache): cache only complete results and failures of the input

Part A2 of #62 (criterion 3), on `main` after #68. The outline artifact (B, `feature/62-outline-artifact`) follows on top of it.

## What
- **The kernel says why a run failed:** the run path's summary (`stepv_occt_run*`, and so `stepv-occt`'s line) gains `"cause"`, null on success. The `--serve` and `--outline` error lines carry no cause; plan.md says so.
  - `"input"`: the file, once opened, doesn't read or transfer; it has an unsupported extension, nothing to draw, or assembly nesting past 64; or OCCT threw on its data.
  - `"environment"`:
    - the kernel can't open the input (it now `open`s it before the reader: "cannot open input: Permission denied");
    - path resolution, mesh output open or write, missing external part files (including nothing to draw because of them);
    - out of memory (`Standard_OutOfMemory` is caught before `Standard_Failure`);
    - invalid arguments, or any other exception.
  - Rust reads it as `occt::Cause`, `Summary.cause` with `#[serde(default)]`. An older kernel gives none, and its failures are not cached.
- **The negative cache rule:** only `Outcome::Failed` whose cause is `input` writes a `.fail`. Timeouts and memory caps depend on limits that aren't in the key; crashes may not repeat; environment failures are outside the key. Each of those, cached, would block a run that could succeed.
- **Only complete results:**
  - `Ok` without a summary is a "bad kernel output" error, and not cached;
  - a multi-file assembly drawn with `external_missing > 0` is not cached, since its part files aren't in the key.
- **Docs:** plan.md "Cache (#62)" (policy and known limits, among them a part file edited after caching), the CHANGELOG, and the header in `stepv_occt.h`.

## Tests (`tests/cache.rs`)
- Each of these caches nothing, and the next run succeeds:
  - a timeout;
  - a memory cap;
  - a kernel exit 0 without a summary;
  - an unwritable mesh output (`TMPDIR` read-only, cause `environment`);
  - missing part files (cause `environment`): none, then one of two (draws, not cached), then both back (cached).
- A garbage `.step` (cause `input`) caches its failure, and the next run serves it.
- Every cause class is covered:
  - a file with no geometry and an OCCT exception (test hook `STEPV_OCCT_TEST_THROW=failure`) are `input`, and cached;
  - a `chmod 000` copy (skipped, with a printed reason, as root) and OCCT's out of memory (`STEPV_OCCT_TEST_THROW=oom`) are `environment`, and cache nothing. The copy, readable again, then succeeds;
  - invalid arguments (the kernel's C library, `dlopen`ed) are `environment`.
- A complete run has a null `cause`.
- Against `origin/main`'s `main.rs`, 5 of these fail: memory cap, no summary, unwritable mesh, missing parts, and bad input (no `cause`).
- Also fixes #70's first item, in `src/cache.rs`. The cross-process writer helper now panics without its env vars, and the parent checks each child's output for `1 passed`. With the filter misspelled, the child runs 0 tests and the parent now fails.
- Review round 1, against the previous head's kernel (`b7083e2`): the `chmod 000` test fails with cause `input`, and the throw-hook test fails because that kernel has no hook.
- Local gate (`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`) after `just kernel`: exit 0, 238 passed.
