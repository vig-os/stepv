# [PR 84](https://github.com/vig-os/stepv/pull/84) feat(cli): show progress on a terminal, and leave the outline from view (#63 part 1)

Refs #63 (part 1 of 2; does **not** close it). Part 2 is #85.

## Why split

All of #63 is well over the ~400-line cap: part 1 alone is +376/−22. Following the brief's own suggestion, this PR is the CLI half. Part 2, the viewer's outline-first window, is #85: it opens before the run finishes, shows the tree, a progress indicator and an honest message when the run is killed or times out, uses a cached artifact before any kernel event, and swaps in the meshes on `Done`.

## What changed

- **Progress on a terminal** (`Progress` in `src/main.rs`). When stderr is a terminal, the run is streamed and one line there is redrawn in place:
  - `stepv: reading`
  - then `stepv: N parts · reading`, as soon as the outline arrives, or at once from a cached outline artifact, before the kernel writes anything
  - then `· transferring P%` and `· meshing P%`, redrawn on each whole percent
  - the line is erased when the run ends.

  A pipe gets nothing on stderr. Stdout's JSON line is unchanged.
- **`stepv view` writes the outline artifact.** Its load is streamed like a cached CLI run's, keyed on the `FileId` taken before the run, and the box is added after the mesh decodes. `--no-cache` writes nothing.
- **Docs.** plan.md has a "#63 part 1" section (what's shown when, the exact messages, known limits with their issues), and the artifact section's "`view` does not write it yet" limit is removed. CHANGELOG has an entry.

## Tests (each fails on `origin/main`)

- `tests/progress.rs` (stderr on a real pty via `libc::openpty`):
  - the terminal shows the part count and `transferring 100%` / `meshing 100%`, never a newline, and ends erased. The same run into a pipe writes no progress and gives the same JSON keys and values. Before the change: `"stepv: reading" not in ""`.
  - a cached artifact names the parts with a kernel that never writes a byte; with no artifact, no count is shown. Before the change: no part count.
- `tests/cache.rs` `a_viewer_killed_after_its_outline_leaves_the_artifact`: a `view` whose kernel stalls after the outline and is killed at a 10 s timeout leaves the artifact at the pre-run key, equal to `occt::outline`, with no box. Before the change the load wasn't streamed, the run completed, and a window opened (`(-1, None)` vs `(4, "timeout")`). `STEPV_VIEW_SCREENSHOT` now makes such a window close itself, so a regression fails instead of hanging.

## Review round 1 (e15cb95)

- **Pty fd leak (blocker):** the test's master and slave are close-on-exec from the moment they exist: `posix_openpt(O_RDWR|O_NOCTTY|O_CLOEXEC)`, and the slave is opened through `std::fs::OpenOptions`, which always sets `O_CLOEXEC`. Setting `FD_CLOEXEC` after `openpty` would still leave a window in which a parallel test's spawn inherits them. The test asserts both flags.
- **Every `view` test is bounded (#86)** through `Home::view`:
  - the kernel runs under `--memory-mb 1024`
  - `STEPV_VIEW_SCREENSHOT` is set, so a window that opens closes itself
  - the viewer's own footprint is polled, and the run is killed and failed past 2 GiB or 120 s.
- **New tests:**
  - `view --no-cache` leaves no artifact, while the same run with the cache on leaves one. It uses a kernel that crashes after a full run, so no window opens. A mutation that makes `view` ignore `--no-cache` fails it (`--no-cache wrote an artifact`).
  - a complete `view` stores the box, equal to the summary's.
- **Docs:** plan.md now says what Ctrl-C leaves: stepv installs no signal handler, so the last state stays on the line. The "viewer still waits" known limit and the CHANGELOG point at #85.

## Fix round 3 (a420b8b): no window session (#84's CI failure)

- **What failed:** in nix's macOS builder (`_nixbld`, with no window-server session), `a_complete_view_adds_the_box` saw `null`. That was the whole JSON report, not the box: the test panicked at its status assertion and never read the box. `stepv view` ran the kernel, then died inside `eframe::run_native`, where macOS's window layer aborts a process that has no session, and stdout's report died with it.
- **Fix (option A, decided):** `view::session` checks before the kernel. On macOS it uses `CGSessionCopyCurrentDictionary`; elsewhere on Unix, `DISPLAY` or `WAYLAND_DISPLAY`. With no session, `view` fails at once: exit 3, `error`, `"no window session: …"` with the reason, and the header metadata.
- **Tests:**
  - A new nextest test: with no session (the `STEPV_VIEW_TEST_NO_SESSION` hook, plus no `DISPLAY`), `view` fails that way and never starts the kernel. It fails without the check.
  - The four `view` tests that need a window are `#[ignore = "needs a window session; run by just view-test"]`. `scripts/test-window-tests.sh` runs them with `--ignored`, and fails unless every one of them ran and passed.
  - CI runs that script on the macOS runner, through `just view-test` in kernel.yml's "GPU viewer on Metal" step, and under Xvfb in the "Viewer (Linux, lavapipe)" job (`scripts/test-linux-viewer.sh`).

- **f391227:** the first CI run of `a420b8b` failed `a_terminal_sees_the_parts_and_each_stage_and_stdout_is_unchanged` in nix's macOS sandbox. There the kernel's sandbox cannot nest (`macos-outer`), and stepv warns about it on stderr after erasing the progress line, which is the documented behavior. The test had forbidden any newline at all. It now checks the rule itself: no newline while redrawing, the erase right after the last redraw, and no progress after it.
- **CI at f391227 runs the window tests on both platforms:** Kernel (macos-15), in its "GPU viewer on Metal" step (`scripts/test-window-tests.sh`), and Viewer (Linux, lavapipe), under Xvfb, each with `4 passed; 0 failed`. Every check is green.
