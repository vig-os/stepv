# [PR 151](https://github.com/vig-os/stepv/pull/151) feat(graph): G1, the Part 21 scanner and entity table

Fixes #133

This is slice G1 of ADR-0001 (`docs/adr/0001-graph-core.md` §2.1, §2.4, §6), implemented as written. The one exception is the duplicate-id rule, below.

## What changed
- **`src/graph/lex.rs`**: a single-pass Part 21 scanner over the mapped bytes. It handles the banner, `HEADER`, edition 3 `ANCHOR`/`SIGNATURE` (skipped) and parameterised `DATA(…)`, simple and complex records, strings with `''`, binaries and comments.
- **`src/graph/mod.rs`**:
  - `Graph` (`open` over `memmap2`, `from_bytes`) with the §2.1 columns: `#id` `u32`, interned type `u16`, arg span `u64`+`u32`.
  - The id lookup is dense at ≤ 4× sparsity, otherwise sorted.
  - `header()` goes through `header::parse_head` (`header::read`'s parser) on the mapped head, with `product_count` taken from the table.
  - The public API so far: `Node`, `StepId`, `TypeName`, `GraphError { offset, kind }`, `len`, `nodes`, `node`, `resolve`, `id`, `type_name`, `duplicate_ids`, `data_parameters`.
- **`src/header.rs`**: `decode_string` drops CR and LF inside strings before `decode_part21`. The header path uses it now, and G2's `Untrusted::decode` will use it too.
- **`examples/graph_scan.rs`**: scan time and heap, measured with a counting global allocator.
- **Dependencies**: `memmap2 = "0.9.11"` (already locked through winit), and `regex` as a dev-dependency for the test oracle.

## Duplicate ids: the ADR's premise doesn't hold (#149)
OCCT doesn't keep one definition. It keeps every record and resolves each reference to the nearest earlier definition, else the nearest later one (`StepData_StepReaderData::SetEntityNumbers`). `occt::outline` confirms it on three orderings: `A,#6,B → A`, `#6,A,B → A`, `A,B,#6 → B`.

- `Graph::resolve(id, from)` implements that rule.
- `Graph::node(id)` gives the first definition.
- `graph::tests::duplicate_ids_resolve_as_occt_does` runs the kernel as the oracle.
- G2's CSR must call `resolve`.

## Acceptance
- **Regex oracle**: on every `tests/data` STEP file (multifile included), the table equals an independent regex pass over ids and types.
- **Duplicate ids**: agree with `occt::outline` (above).
- **Malformed inputs**: the fetched set and an in-test rebuild of `fetch-fixtures.py`'s cases from `tests/data` are all refused with an offset, and nothing panics.
  - **Exception: `header-only.step`** is valid Part 21 with an empty `DATA` section. None of §2.1's refusal rules applies, so it gives an empty graph.
- **§2.7** (sage, release build, `graph_scan`):

| File | Entities | Scan, cold / warm | Heap, without `referrers` | Peak |
| --- | ---: | --- | --- | --- |
| Ultimaker 3 (143 MB) | 1,517,999 | 0.55 / 0.19 s (≤ 1.0) | 33.4 MB, 22.0 B/entity (≤ 36) | 56 MB |
| Stress (221 MB) | 3,283,040 | 1.12 / 0.32 s (≤ 1.5) | 72.2 MB, 22.0 B/entity (≤ 120 MB) | 115 MB |

- **Local corpus**: 389 files, 0 refusals, 0 panics, 2.3 s serial scan in total (≤ 20 s).

## Size
About 580 non-blank, non-comment product lines (`lex.rs` 293, `mod.rs` 288). That is over the slice's ~400. The split is proposed to the architect.
