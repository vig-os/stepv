# [PR 188](https://github.com/vig-os/stepv/pull/188) feat(graph): G5, the stepv graph CLI

Fixes #137

Slice **G5** of ADR-0001 (§2.4, §2.7, §6).

## What changed
- **`stepv graph summary|census|tree|query <input>`** (`src/graph_cmd.rs`, wired in `src/main.rs`). Prints the file's own graph as one JSON value on stdout, with no kernel involved:
  - `summary`: the header, the units, the census totals, the structure's size and the model box.
  - `census`: entity instances per type and per part.
  - `tree`: one page of the occurrence tree. It takes `--depth`, `--offset` and `--limit`, and `"next"` gives the next page's offset. The outline's caps apply.
  - `query <filter>`: jq via jaq, over the lazy view.
  - `--timings` on all of them, on stderr.
  - Exit codes: 2 for a usage error or a filter that doesn't parse or compile (message and byte offset on stderr). 3 when the file is refused, a cap is hit, or the filter fails at runtime.
- **`src/graph/json.rs`** (always built): `View` computes `structure()` and `bounds()` the first time they're used, times them, and writes the JSON. Every string from the file is written as `{"untrusted": "…"}`. That covers header fields, names, type names, enums and string arguments. File text is never a bare string or a key, which is why the census is a list of `{"type", "count"}`.
- **`src/graph/query.rs`** (behind the new default-on `query` feature, so stepv-capi doesn't build it): `query(&View, filter, limit)`.
  - Native filters: `summary`, `census`, `products`, `tree`, `entity($id)`, `refs($id)`, `referrers($id)`.
  - `env`, `halt` and the logging natives raise an error, so a filter can't read the host or end the process.
- **ADR §2.4** now records the realised API, the ValT-vs-native decision and the measured numbers.

## ValT vs native filters: native
- jaq 3's `ValT::values`/`key_values` return `'static` iterators. An `Entity(Node)` variant would therefore have to own the graph, and the whole `Val` surface would have to be re-implemented.
- The native-filter fallback passes the heap test:
  - the graph's heap (table + `referrers`) is **127.9 MB**;
  - the peak through a one-part face walk (663 faces) on the stress assembly is **179.3 MB (1.40×, bar 2×)**.

## Tests
- `nix develop -c cargo test --test graph_cli`: exit 0, 8 passed.
  - Golden JSON in `tests/golden/graph/` for `summary` (assembly and sketch), `census`, `tree`, a paginated page and `--depth 0`.
  - An injection-style name (product, NAUO and header) only ever appears as a lone `"untrusted"` value, checked in `summary`, `tree`, `query products/tree/entity/summary`.
  - A real face walk is checked against an independent count from the graph's API.
  - Malformed filters exit 2 with a stderr message, nothing on stdout and no panic.
  - `--timings` output is on stderr only.
  - The heap test needs `STEPV_CORPUS`: it skips loudly when that is unset and fails when the variable is set but the file is missing.
- `nix develop -c cargo test graph::`: exit 0, 48 passed.
- Local gate: `cargo fmt --check`, `clippy --all-targets` with and without default features, and the full `cargo test`. Exit 0.
- Before the change, the test file fails to compile (`unresolved import stepv::graph::json` / `stepv::graph::query`). It has `required-features = ["query"]`, so it can't pass vacuously on main.
