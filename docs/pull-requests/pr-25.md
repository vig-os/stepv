# [PR 25](https://github.com/vig-os/stepv/pull/25) fix(kernel): say why a multi-file assembly is empty

## Description

#19, option 1 (the minimum, with no wider file access): a multi-file STEP assembly whose part files can't be read no longer fails as an unexplained "no geometry".

OCCT's `STEPCAFControl_Reader` skips a part file it can't open **silently**. That happens when the siblings are missing, and in Quick Look, whose App Sandbox grants the extension only the previewed file. The kernel now reads the reader's `ExternFiles()` after transfer and counts:

- `external_files`: the part files the assembly references;
- `external_missing`: the ones whose load status isn't `RetDone`.

With nothing left to draw, the error names the cause: `multi-file assembly: 2 of 2 part files it references could not be read`. The Quick Look preview adds: *"⚠ Multi-file assembly: N of M part files are not shown. Quick Look can open only this file; `stepv view` shows the whole assembly."*

Widening Quick Look's read access (option 2) stays undecided. plan.md §6 in #23 records the trade-off: it would expose more of the disk to a hostile file.
