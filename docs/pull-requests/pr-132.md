# [PR 132](https://github.com/vig-os/stepv/pull/132) docs(adr): ADR-0001, the graph core and the Rust fast path for analytic products

Adds `docs/adr/` (an index, plus ADR-0001), the design for the milestone "MVP: graph core", following the owner's rulings of 2026-11-08: graph core first, Rust meshing of analytic primitives in the MVP, and hardening filed as issues for later. Docs only, no code.

**Round 2:** fixes the review's three blockers (the occurrence DAG, complex entities, units scaled per placement), records the owner's §7 decisions, and folds in every nit.

## Key decisions
- **Parser:** hand-written Part 21 scanner over `memmap2`: an entity table, CSR references, and arguments parsed on access. Complex entities are first-class (`is_a`, `parts`, `args_of`; `of_type` matches parts). Edition 3 `DATA(…)` is read, `ANCHOR`/`SIGNATURE` are skipped, and `REFERENCE`/`<…>`/`@n` are deferred. Duplicate ids are kept as OCCT keeps them. `ruststep`, Foxtrot's `step`, `iso-10303` and `truck-stepio` were rejected with reasons.
- **Structure:** a product **DAG** with a cycle check. Leaves are numbered from the DAG without expanding it, identically to `occt::outline`; occurrences expand lazily under the outline's caps (depth 60, 1 M nodes). Both naming rules apply. Each placement item is scaled to mm in its own context before composing. `Structure` is owned data, with no borrow of the `Graph`.
- **Boxes:** computed per geometric type, conservative or `Unknown(reason)`. Local frames are carried through the 8-corner rule, and non-positive weights give `Unknown`.
- **Placeholders:** boxes, plus coaxial-cylinder and concentric-sphere fits that contain the exact geometry, drawn circumscribed and styled like the boxes (§2.8).
- **Fast path:** canonical edge polylines (conics and B-spline curves), analytic faces meshed through a `spade` CDT, rayon, and whole-product routing with a ledger. There are two gates: every triangle within d of the exact surface, and a sampled Hausdorff distance ≤ 2·d against OCCT, with the distances recorded and the tightening filed. The graph is the source of truth for names and colours; XCAF is the oracle, and M5's parity check is a CI gate.

## Slice plan (each ≤ ~400 product lines; details and test commands in ADR §6)
| Slice | Scope |
| --- | --- |
| G1 | scanner + entity table (edition 3 `DATA`, CR/LF, duplicate ids) |
| G2 | CSR + lazy args + complex parts + census (gates the M slices) |
| G3 | structure DAG + caps + placements in mm (inch-in-mm fixture) |
| G4 | conservative boxes; each product's box ⊇ OCCT's on the corpus |
| G5 | `stepv graph` CLI (summary/tree/census/query via jaq) |
| G6a | the viewer opens on the graph with box placeholders |
| G6b | meshes replace placeholders; mismatch rule; `OutlineArtifact::boxes` |
| G6c | cylinder and sphere fits (conservative, circumscribed) |
| G7 | colours from the graph, named style cases, parity with XCAF |
| M1a / M1b | analytic edges / B-spline edges (both MVP) |
| M2 | planar faces with holes (spade) |
| M3 | cylinder, cone, sphere, torus |
| M4a | classify + ledger + rayon; surface gate and OCCT gate |
| M4b | combined view, cache key |
| M5 | kernel `--products`, face and edge ids, parity CI gate, Ultimaker timing |
