# [PR 95](https://github.com/vig-os/stepv/pull/95) feat(kernel): read the input from an inherited fd, with --format (#91)

Closes #91. Refs #64, #79, #92.

#64's Quick Look service holds the file only as a descriptor. The kernel now reads one: `stepv-occt /dev/fd/N --format step|iges|brep`.

## Design
- **`/dev/fd/N`, not `--fd N`:** the input stays a path, so OCCT's path-based readers (STEP, IGES, BREP) keep working without change, on macOS (devfs) and on Linux (`/proc/self/fd`). #79 round 2 showed that `open("/dev/fd/3")` works inside the service's sandbox. An input that is exactly `/dev/fd/N` (`kernel/input.h`) is never `realpath`ed, and it's rewound before reading: on macOS, opening `/dev/fd/N` shares N's offset.
- **`--format`:** required with a descriptor. With a path it's optional and overrides the extension. `--outline` and `--serve` take it too. In the C ABI, `stepv_occt_run_stream`, `stepv_occt_outline` and `stepv_occt_serve` gain a `format` argument (NULL means by extension). `stepv_occt_run`, which the Quick Look extensions call, keeps its signature.
- **Causes:**
  - A missing `--format`, an unknown `--format`, or a descriptor that isn't open or can't seek fails at `read` with **`environment`**. The caller asked wrongly, the same file reads when asked right, and #62's front-end must not remember the file as bad.
  - A file that doesn't read as the named format fails with **`input`**, as a STEP file named `.igs` always has.
- **Sandbox:** a descriptor's read grant is `/dev/fd/N` alone. Seatbelt matches that name. Landlock's rule is opened through the magic link, so it lands on that one file. Nothing is reachable by path, the file's directory included.
- **Rust:** `occt::Input` (`Path(&Path)` / `Fd { fd: BorrowedFd, format: occt::Format }`) for `occt::run`, `run_streaming` and `outline`. `&Path` and `&PathBuf` convert, so existing callers don't change. The descriptor is inherited at its own number: close-on-exec is cleared in the child only, through `pre_exec`. `libc` moves from a macOS-only dependency to all of unix.
- **Known limit:** part files of a multi-file assembly can't be reached from a descriptor. They are reported in `external_missing` with cause `environment`, as missing files are by path. Follow-up: #92.

## Tests (each fails on the previous kernel: `cargo test --test fd` with `STEPV_OCCT=<main kernel>` exits 101, 3/3 failed)
- `tests/fd.rs`:
  - STEP, IGES and BREP passed as fd 3, with the file deleted after it was opened: the summary (minus timings and peak RSS) and the mesh bytes equal a run by path.
  - No `--format` and `--format dwg` give `environment`. A wrong format gives `input`.
  - `occt::run` and `occt::outline` through `Input::Fd` match the path run. A pipe gives `environment`.
- `tests/sandbox.rs`: with an fd input, reading the input's sibling file is refused by the sandbox, and the run still does its work.
