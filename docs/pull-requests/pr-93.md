# [PR 93](https://github.com/vig-os/stepv/pull/93) feat(view): open the viewer on the outline, and cancel the run on close (#85)

Closes #85

## What

`stepv view` opens its window **at once** and runs the kernel on a thread of its own (`run_view` / `load_view` in `src/main.rs`), through the CLI's own `tessellate`, so the artifact, the box and the progress code are shared, not duplicated. The loader sends the window `view::Load` messages over a channel:

- **`Tree`:** a cached outline artifact's tree, sent before the kernel starts, then the run's `Event::Tree`. It's drawn in the tree panel (`Tree::from_nodes`).
- **`Progress`:** "Transferring the shapes: P%" or "Meshing: P%", with a progress bar.
- **`Done`:** the GPU scene is built and the viewer swaps in, with the full title.
- **`Failed`:** the window closes and the report says why, as before. #89 will keep the tree with its reason instead.

**Closing mid-load cancels the run (Q1).** `occt::run_streaming` gains a `cancel: Option<&AtomicBool>` parameter. `supervise`'s tick may stop the run and kill the kernel, which is the new `Outcome::Cancelled`. `view` reports status `cancelled` with exit 0. This public API change is in the rustdoc and the CHANGELOG.

**Known limits.** `--software`, or no usable GPU, still waits for the whole run (#90). A failed run closes the window (#89).

## Tests (each new one fails on `origin/main`)

- `tests/stream.rs` `a_cancelled_run_is_killed_at_once` (nextest): `Outcome::Cancelled`, no summary, within seconds of a 60 s cap.
- Window tests: `#[ignore = "needs a window session; …"]`, run by `scripts/test-window-tests.sh`, which now counts 7. They go through `Home::view` (process group, memory cap, `--timeout`, screenshot hook). Under `STEPV_VIEW_SCREENSHOT` the window reports its frames on stderr, because the macOS CI runner never presents a window:
  - `the_viewer_shows_the_tree_before_the_geometry`: with the kernel stalled 8 s, the loading frame shows the outline's rows and no geometry, then the scene. On `main`: `no loading frame with the tree`.
  - `a_cached_outline_shows_the_tree_before_any_kernel_event`: a cached artifact with a mute kernel shows the artifact's rows. On `main`: no loading frame.
  - `closing_the_viewer_mid_load_cancels_the_kernel`: `STEPV_VIEW_CLOSE_LOADING=1` with a stalled kernel gives `cancelled`, exit 0, in under 20 s, and the kernel's process is gone. On `main`: `(4, "timeout")` after 30 s.
- The existing watchdog test's deadline goes from 2 s to 10 s. The window now opens alongside the run, and macOS's first-launch check of the test's fresh kernel script was measured at up to 1.5 s, which made 2 s flaky. That's still far below stepv's own 30 s timeout.
- The no-session early failure (#84) is unchanged and still passes in nextest.

## Review round 1 (ed150e9)

- **Software fallback (blocker):** the viewer's pipelines are now built and validated in eframe's creator (`pipelines()` in `src/view/app.rs`), before the window is the viewer's. A refusal hands the load back, and `view::run` falls back to software, as on `main`. Only the scene's buffers are checked after `Done`.
  - New window test `a_gpu_that_refuses_the_pipelines_falls_back_to_software`, using the `STEPV_VIEW_REJECT_PIPELINES` hook: status `ok`, backend `software`, and the screenshot is drawn. At f18f607 it fails with `backend: "metal"`.
- **Loader panic:** the loader takes the `Sender` by value, so a panic closes the channel. A unit test checks that a panicking loader ends the software viewer's wait.
- **`cancelled` report:** it carries `message`, not `error` (documented in plan.md); the cancel test asserts it.
- **CHANGELOG:** the `run_streaming` change is under **Changed**, marked breaking.
- **Harness:** `Outcome::Cancelled` maps to a `Crash` verdict with a note, instead of `unreachable!`.
