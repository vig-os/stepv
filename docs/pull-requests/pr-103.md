# [PR 103](https://github.com/vig-os/stepv/pull/103) fix(kernel): read an input descriptor directly, never re-open /dev/fd/N (#102)

## The kernel reads an input descriptor directly (#102)

Closes #102. Refs #91, #64, #98.

### The bug
#91 passed `/dev/fd/N` as a path and let OCCT's path readers re-open it. On CI's `macos-15-arm64` runner, the sandbox the kernel inherits from #64's Quick Look service denies that re-open: `cannot open input: Operation not permitted` (#98's CI). macOS 26.4 allows it. The root cause is the re-open by name, so the kernel now reads the open descriptor and never `open()`s `/dev/fd/N`.

### The choice, per format (probed in OCCT 7.9.3's sources and headers)
- **STEP: A, a stream over the fd.**
  - `STEPCAFControl_Reader::ReadStream` for runs, `STEPControl_Reader::ReadStream` for `--outline`.
  - `StepSelect_WorkLibrary::ReadFile` and `ReadStream` both call `StepFile_Read`. The path version only opens an istream first, so the parser is identical.
- **BREP: A.**
  - `BRepTools::Read(shape, istream, builder)`.
  - The path overload opens an istream and runs the same `BRepTools_ShapeSet` reads.
- **IGES: B, a private copy.**
  - `IGESSelect_WorkLibrary` doesn't override `IFSelect_WorkLibrary::ReadStream`, whose default returns failure, so there is no IGES stream reader.
  - The kernel copies the fd to `$TMPDIR/stepv-input-XXXXXX.igs` (its real path, because macOS's `/var` is a symlink) and reads that by path.
  - `stepv-occt` makes the copy before its sandbox and grants that one file.
  - The sandbox can't let the kernel remove a file it may read (Landlock removes through the parent directory). A child forked before the sandbox, holding only its end of a pipe, unlinks the copy when the pipe closes. On a normal exit the kernel waits for it, and a killed kernel still has its copy removed.
- `FdStreamBuf` reads with `pread` from offset 0, so the caller's shared file offset is no longer moved.
- **Sandbox:** a descriptor input is now granted nothing by path, not even `/dev/fd/N`.

### Tests
- **New in `tests/fd.rs`: `the_kernel_reads_its_descriptor_without_reopening_it`.**
  - The file is set to mode 000 once open, so re-opening `/dev/fd/N` fails on macOS (fdesc) and Linux (`/proc/self/fd`) alike.
  - Run, `--outline` and `--serve` must equal the path's, for STEP, IGES and BREP.
  - **It fails on the previous kernel** with `cannot open input: Permission denied`, the macOS 15 failure.
- **New: `the_iges_copy_is_unlinked`.** With a private `$TMPDIR`, nothing is left after a successful run or a failed one. This test caught the in-sandbox unlink failing, which the forked remover fixes.
- The #91 tests (`tests/fd.rs`, `tests/sandbox.rs`) are unchanged and pass.
