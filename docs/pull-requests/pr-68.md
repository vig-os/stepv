# [PR 68](https://github.com/vig-os/stepv/pull/68) feat(cache): atomic, versioned cache entries

Part A1 of #62 (criteria 1–2 of the brief). Stacked after it:
- **A2**, `feature/62-complete-only`: complete-only caching, the kernel's failure `cause`, and the negative-cache rule (criterion 3). Its PR is stacked on this one.
- **B**, `feature/62-outline-artifact`: the outline artifact (criterion 4). No PR yet.

## What
- **One writer, `cache::write_atomic`**, replacing `main.rs`'s. It writes `<name>.<pid>.<nonce>.part` in the target's directory, `fsync`s it, renames it, then `fsync`s the directory (`#[cfg(unix)]`). A failed directory `fsync` after the rename is not an error: the entry is complete, and at worst a crash loses it and it is regenerated. Every output stepv writes goes through it.
- **Framed, versioned entries:** `cache::store` and `cache::load` frame an entry as magic, `ENTRY_VERSION`, length, payload, blake3. A truncated, corrupt, other-version or raw pre-#62 entry (`.fail` included) is a miss and is regenerated. The hash catches truncation, not forgery: the cache directory is the user's own.
- **Stale `.part` sweep:** `store` removes `.part` files older than `STALE_PART_AGE` (1 h), in the cache directory only. The age is by wall clock, so a writer stopped for longer loses its `.part`, harmlessly (`ENOENT` on rename, nothing corrupted).
- **Docs:** a "Cache (#62)" section in `plan.md`, and a CHANGELOG entry.

## Tests
- `cache.rs` unit tests:
  - 4 **processes** (the test binary re-executed) and 4 threads write 64 KiB entries to one key while a reader verifies each raw frame (length and blake3, not `load`). With `write_atomic` swapped for an in-place `std::fs::write`, it **fails** in 5 of 5 runs, with 14–20 torn reads each. With the real writer it passes in about 7 s;
  - a truncated (4 cuts), old-version, corrupt or raw entry doesn't load;
  - the sweep takes stale `.part` files only.
- `tests/cache.rs`: a truncated entry and an old-version one are each regenerated (`cached: false`), then served. Against `origin/main`'s `main.rs` it fails at `tests/cache.rs:104` (the raw entry isn't a framed one).
- Local gate (`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`), on a kernel built from `main`: exit 0, 227 passed.
