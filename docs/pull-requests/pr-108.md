# [PR 108](https://github.com/vig-os/stepv/pull/108) feat(macos): bound the kernels each supervisor runs at once (#64 PR 2a)

## #64 PR 2a: the supervisor's admission limit

Refs #64. This merges **before** #107 (#64 PR 2), so `main` never ships unbounded kernel concurrency. #107 rebases onto it.

### What changes
- `Admission` in `macos/Supervisor/main.swift`: each service runs at most **L = clamp(physical memory / (4 × 4096 MB), 1, cores)** kernels at once.
  - That's about ¼ of RAM per service, ½ across the thumbnail and preview services.
  - L is 1 on an 8–16 GB Mac and on CI's 7 GB runner, and 16 on sage.
- Requests over L wait in a **FIFO** queue.
  - Their **deadline counts from submission**: queue time is spent.
  - A request that expires or is cancelled in the queue is **withdrawn without spawning a kernel**, and gets its normal deadline or cancelled reply.
- Queueing, admission and withdrawal are logged. Each service also names itself (bundle id) and its L in its start line: the two supervisors are one binary, so the log can't tell them apart by image path.

### Tests (against main's code: the supervisor probe and harness, not the extensions)
- `scripts/ql-e2e/supervisor.sh` builds a **test supervisor** (`-D STEPV_TEST_HOOKS`, never shipped) that reads L = 1 from its bundle. With it:
  - the second of two runs spawns only after the first has ended, checked from the log's order;
  - a run whose deadline passes in the queue **never spawns**.
- The probe's concurrency check follows the service's logged L: at L ≥ 2 the second run finishes beside the first, at L = 1 it is served after it.

### Results (sage)
- `scripts/test-macos.sh`: exit 0 (L = 16, plus the L = 1 test build).
- `scripts/ql-e2e/supervisor.sh` on a copy whose supervisors are the L = 1 build (CI's case): exit 0.
- Product code: +114 lines.
