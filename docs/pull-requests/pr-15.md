# [PR 15](https://github.com/vig-os/stepv/pull/15) feat(kernel): S1 — native OCCT kernel, recovery ladder, harness (99.5% on 391 files)

## Description

Step S1 of `plan.md`: prove a kernel against a real STEP corpus. Plan A (`occt-wasm`) was run and
failed its gate, so this lands **Plan B: native OCCT 7.9.3 as a subprocess**. On 391 files it shows
99.5% of them faithfully; 0 crash and 0 time out.

## Changes Made

- `kernel/stepv-occt.cpp`: STEPCAF/IGESCAF/BREP → XCAF walk → BRepMesh at a bbox-relative
  deflection → the per-face recovery ladder → `STEPVMSH` v2 buffers + a JSON summary that survives
  failure (exit 3). `kernel/stress-gen.cpp` generates the stress fixture.
- `src/occt.rs`: the subprocess driver (timeout = kill) and the `STEPVMSH` decoder.
- `src/lib.rs`: `FaceStatus`, `LineKind`, `Lines`, `Part::is_well_formed`.
- `examples/harness.rs`, plus `just fixtures` (`scripts/fetch-fixtures.py`) with a sha256-pinned
  corpus recorded in `tests/fixtures/corpus.sha256`.
- `flake.nix`: OCCT plus devkit's `native` module. Also fixes the statix/deadnix failures the
  scaffold shipped with (vig-os/devkit#1810).
- `plan.md`: S1 results, corrections (the claim that `tessellateRelative` is bbox-relative; the
  credentials claim), and an issue for every remaining step.

Verification: `cargo fmt --check`, `cargo clippy --all-targets -D warnings`, `cargo test` (19)
and `cargo doc` pass locally. `nix flake check` didn't run locally (sage's build governor held
it), so CI on this PR is its first run.
